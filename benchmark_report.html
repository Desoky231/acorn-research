🚨 Crucial Research Finding: The Disconnection Cliff

1. Catastrophic Accuracy Collapse: When filter selectivity drops below 1%, the predicate subgraph fragments into isolated islands. At ≤ 0.20% selectivity, search accuracy crashes completely from 87% down to 1.50% and 0.15%.

2. The "Fake Speed" Anomaly: The massive throughput surge at 0.01% selectivity (200,705 QPS) occurs because greedy search gets stuck immediately at the entry point after visiting only 1-2 nodes and quits instantly, returning completely incorrect vectors.

3. Need for Pre-Filtering Fallback: This empirically validates that ACORN cannot function independently without an automatic pre-filtering fallback for selective predicates.

In-Depth Source Code Audit

ACORN Codebase vs. Paper Findings

6 critical architectural limitations, unscalable data structures, and code discrepancies identified in ACORN.cpp and ACORN.h.

1
The "Predicate-Agnostic" Lie (Single Label vs. 32-Bit Limit)
Data Structure

The Paper Claim: ACORN supports unbounded, high-cardinality metadata (e.g. lists of tags, keywords, clinical codes).

The Code Reality: In ACORN.h:L235, the index stores a flat array of single integers: const int* metadata;. When indexing node v, it does metadata[v].

// ACORN.h line 235 & ACORN.cpp line 671: const int* metadata; auto metadata = hnsw.metadata[nodeId]; // 1-to-1 array: strictly 1 integer per vector!

The 32-Tag Ceiling: Bitmasking (mask |= (1 << tag)) worked for SIFT1M (12 labels), but is hard-capped at 32 total tags across the database. For datasets with 1,000+ tags (TripClick, LAION), this fails completely.

Proposed Implementation:
Upgrade ACORN and IndexACORNFlat to store dynamic arrays: std::vector<std::vector<int>> multi_metadata;.
2
The "Filter Map" Memory Bomb (1 GB Overhead)
Memory Bloat

The Paper Claim: Predicates are evaluated on the fly during search traversal.

The Code Reality: In ACORN.h:L240, hybrid_search requires an uncompressed char* filter_map matrix of size (nq × nb). For 1,000 queries and 1M vectors, that eats up 1.0 GB of raw RAM before search even starts! On LAION-25M, this consumes 25 GB of RAM and immediately crashes.

// In bench_sift1m_labels.cpp: std::vector<char> filter_map(nq * nb, 0); // 1,000 x 1,000,000 = 1,000,000,000 bytes (1 GB RAM!)
Proposed Implementation:
Rewrite hybrid_search to accept filter tags directly and evaluate predicates on-the-fly when visiting nodes, reducing extra RAM from 1 GB to 0 MB.
3
Missing "Pre-Filtering Fallback" & Proven Graph Disconnection
Accuracy Crash

The Paper Claim: "For highly selective queries where even ACORN's predicate subgraph would be disconnected... ACORN falls back to pre-filtering."

The Code Reality: There is zero routing or fallback logic in ACORN.cpp. It blindly searches the graph even when the graph is completely broken.

Empirical Proof: Our 1M stress test showed that below 0.2% selectivity, accuracy crashes to 0.15% Recall@10 because matching nodes are isolated islands.

Proposed Implementation:
Build a lightweight cost-based router: if selectivity < 1%, automatically divert the query to exact brute-force pre-filtering.
4
Compression is ONLY Applied to Level 0 (Memory Bloat)
Memory Bloat

The Code Reality: In add_link (line 678 of ACORN.cpp), the $M_\beta$ compression function is strictly guarded by if (level == 0). The upper graph levels are completely uncompressed and balloon to $M \times \gamma$ edges. For TripClick ($\gamma=80$), upper levels store 80× more edges than standard HNSW.

Proposed Implementation:
Apply $M_\beta$ compression across all graph levels to prevent upper-layer edge explosion.
